# 認知・判断・行動分析アプリ

参加者がブラウザ上で短い認知課題（リンダ問題・バットとボール問題）に回答し、回答・回答時間・確信度などを記録する Streamlit アプリです。
問題文の表現（標準版／言い換え版）と時間制限（なし／あり）による回答の違いを、条件間で比較するために使います。

> 本アプリは個人の能力や性格を判定するものではありません。特定の課題・条件における回答傾向を集計するためのツールです。

## セットアップ

[uv](https://docs.astral.sh/uv/) が必要です。

```sh
uv sync
```

### 実験者パスワード

実験者画面を使うには、パスワードを次のどちらかで設定します。未設定の場合、実験者画面は開けません。

- `.streamlit/secrets.toml` に `admin_password = "..."` と書く（このファイルは git 管理外）
- 環境変数 `COGEXP_ADMIN_PASSWORD` を設定する

予備実験・本実験の前に、推測されにくいパスワードにしてください。

## 起動

```sh
uv run python scripts/dev.py app
```

| 画面 | URL |
| --- | --- |
| 参加者画面（予備実験） | `http://localhost:8501/?exp=pilot_v1` |
| 参加者画面（動作確認用） | `http://localhost:8501/?exp=check_timeout_revision` |
| 実験者画面 | `http://localhost:8501/admin` |

- 実験定義が複数あるため、参加者画面の URL には必ず `?exp=<実験ID>` を付けます。
- **受付は既定で停止しています。** 実験者画面の「条件設定」タブで、実験ごとに「受付を開始する」を押してから参加者画面を開いてください。
- 実験定義（YAML）や文面を変更したら、アプリを再起動してください。

## 実験定義

実験定義は `experiments/` にあります。詳しいルールは [experiments/AGENTS.md](experiments/AGENTS.md) を参照してください。

| ファイル | 内容 |
| --- | --- |
| [experiments/pilot_v1.yaml](experiments/pilot_v1.yaml) | 予備実験 v1。表現（標準／言い換え）× 時間制限（なし／15秒）の4条件。出題順（リンダ先／バットとボール先）を均等化 |
| [experiments/check_timeout_revision.yaml](experiments/check_timeout_revision.yaml) | **動作確認用**。制限15秒・残り時間表示・見直しありの1条件のみ。研究データには使わない |
| `experiments/tasks/*.yaml` | 問題文の版（`task/variant@version`）。公開済みの版は書き換えない |
| `experiments/texts/*.md` | 参加者向けの説明・同意・終了などの文面（【】は倫理審査に合わせて確定する） |

### 条件の主な設定項目

| 項目 | 意味 |
| --- | --- |
| `time_limit_sec` | 制限時間（秒）。書かなければ制限なし |
| `show_countdown` | 残り時間を表示するか（制限の有無とは独立） |
| `collect_confidence` | 回答後に確信度を尋ねるか |
| `allow_revision` | 全問回答後に見直しを行うか（見直しは事前に告知しない／制限時間なし） |
| `variants` | 提示する問題の版 |

実験全体の設定として `practice`（練習課題）、`counterbalance_order`（出題順の均等化）、`abandon_after_min`（放置とみなす分数）があります。

## 動作確認の手順

自動テスト（`dev.py check`）に加えて、ブラウザで次を確認できます。動作確認で記録したデータは実験IDで区別でき、`check_timeout_revision` のデータは分析から除外してください。

### 基本の流れ・割当・中断（`pilot_v1`）

1. 実験者画面で `pilot_v1` の受付を開始する。
2. `/?exp=pilot_v1` を開き、同意して最後まで回答する。数値の問題は Enter キーでも送信できる。
3. タブを開き直して何回か参加し、実験者画面の「条件設定」タブで、条件 × 出題順の組に1人ずつ割り当てられていくことを確認する。
4. 途中でページを再読み込みし、「参加が中断されました」と表示され、実験者画面で中断として数えられることを確認する。

### 時間切れ・見直し（`check_timeout_revision`）

1. 実験者画面で「動作確認用（時間切れ・見直し）」の受付を開始する。
2. `/?exp=check_timeout_revision` を開き、同意して進む。
3. 本番の1問目は何もせず15秒待つ。残り時間が0になると自動で次の問題に進む（時間切れとして記録される）。
4. 2問目に回答すると「回答の見直し」に進む。最初の回答が表示・選択済みの状態で再表示され、変更してもそのままでもよい。見直しには制限時間がない。
5. 実験者画面の「見直し」タブで、回答変化率と初回 × 見直し後の正誤の集計を確認する。

### 操作ログ（マウス軌跡など）

1. どちらかの実験で、マウスを動かしたり選択肢を選び直したりしながら回答する。
2. 実験者画面の「操作ログ」タブで、ログ取得状況（ブラウザ・OS・入力の種類別）、試行別の指標、軌跡の図を確認する。
3. 軌跡の図のスライダーを動かすと、表示開始からその時点までの軌跡が表示される（簡易再生）。
4. 可能なら Chrome・Edge・Firefox など複数のブラウザ、マウスとタッチパッドで確認し、ログ取得率が下がらないことを確かめる。

確認が終わったら、動作確認用の実験の受付を停止してください。

## データ

- 保存先：`data/cogexp.sqlite`（git 管理外）。項目の定義は [docs/data_dictionary.md](docs/data_dictionary.md)。
- 実験者画面の「実施状況」タブから、生データ（participants / trials / events）を CSV で、条件設定と問題文の版を JSON で出力できる。
- 同意前・不同意の参加者のデータは保存しない。氏名・メールアドレスなどの直接識別情報は取得しない。
- 回答と確信度の画面では、マウスの座標・クリック・選択の変更・キー操作の種類（入力した文字は記録しない）・タブの切り替えを記録する。端末情報はブラウザ・OS の種類、画面の大きさ、入力の種類のみ。
- 保存項目を変更したバージョンに更新した場合、古いデータファイルは起動時にエラーになる。ファイル名を変えて退避し、新しいファイルで開始する。

## 開発

```sh
uv run python scripts/dev.py check   # 完了前の必須ゲート（整形・lint・型・構造チェック・テスト）
uv run python scripts/dev.py fmt     # 整形
uv run python scripts/dev.py lock    # 新しい問題文の版をロックに登録
```
