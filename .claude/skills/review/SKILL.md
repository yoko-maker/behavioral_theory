# レビュー（Codex `review-agent` を本プロジェクト向けに調整）

対象を直接調べ、作者が直すであろう指摘をすべて返す。ファイルの変更・コミットはしない。

## 手順

1. ルート `AGENTS.md` と、変更されたディレクトリの `AGENTS.md` を読む。
2. 差分全体と、変更経路を理解するのに必要な周辺コードを読む。最初の問題を見つけても差分の最後まで続ける。
3. 関連するテスト・呼び出し元を確認し、指摘が実在し対処可能であることを確かめる。
4. `uv run python scripts/dev.py check` の結果も確認する。

## 指摘する条件（すべて満たすもののみ）

- 正しさ・研究データの完全性・参加者保護・セキュリティ・保守性に意味のある影響がある。
- 個別に対処可能で、この変更で持ち込まれた。
- 影響するシナリオをコードから示せる。

推測の懸念、既存の問題、意図的な仕様変更、可読性を損なわないスタイル指摘は出さない。

## 本プロジェクトで特に見る点

- 同意前に trial/event が保存される経路がないか。
- 時間切れ・未回答・中断が誤答（`is_correct=False`）に畳み込まれていないか。
- Streamlit の再実行・二重クリックで回答行が重複しないか（`submission_id` の冪等性）。
- 公開済みの問題文の版が書き換えられていないか、条件が版を明示参照しているか。
- 時刻・乱数が注入されているか（seed が保存されるか）。
- 直接識別情報が保存・エクスポートに含まれないか。
- 条件間で、条件設定以外の画面差（文言・配置・演出）が生じていないか。
- 結果を能力・性格・「直感的思考」と断定する文言がないか。

## 出力

優先度順に1件ずつ：

`[P1] 命令形の指摘タイトル — path/to/file.py:line`

続けて、影響するシナリオと何が誤っているかを短い段落で書く。

- `P0`：データ消失・同意違反・識別情報漏えいなど、予備実験を実施できない欠陥
- `P1`：データの誤記録・条件の取り違えなど、次に直すべき欠陥
- `P2`：通常の欠陥
- `P3`：影響は小さいが直す価値のあるもの

指摘がなければ `No findings.` と書く。最後に全体評価と、テストの不足・残るリスクを簡潔に述べる。
