# フェーズ1：最小実用版（MVP）実行計画

概要書 §13 フェーズ1・§14・§15 に対応する。エージェントは作業前にこのファイルを読み、
完了したタスクのチェックを更新する。各タスクは「完了条件」を満たし `dev.py check` が PASS したら完了。

## マイルストーン

### M1 ドメイン層

- [ ] `domain/flow.py`：画面遷移の状態機械（説明→同意→操作説明→練習→本課題→確信度→終了）
  - 完了条件：同意しない場合に課題状態へ遷移できないことをテストで確認
- [ ] `domain/scoring.py`：正誤判定（選択式・数値入力式・正答定義なし）
  - 完了条件：`outcome != answered` で `is_correct` が None になることをテストで確認
- [ ] `domain/timing.py`：時間切れ判定（FakeClock で境界値テスト）
- [ ] `domain/assignment.py`：seed 付きの条件割当・出題順（同じ seed で同じ結果）

### M2 保存層

- [ ] `storage/repository.py`：SQLite リポジトリ（participants / trials / events）
  - 完了条件：同一 `submission_id` の再送で行が増えず `duplicate_submission_count` が増える
  - 完了条件：未同意の参加者の trial 書き込みが拒否される

### M3 参加者フロー UI

- [ ] `app/main.py`：参加者フロー（AppTest で同意拒否・完走・時間切れのシナリオを検証）
- [ ] 選択式・数値入力式の回答 UI、確信度入力
- [ ] 回答確定後のボタン無効化と確定済み表示

### M4 実験者画面

- [ ] アクセス制限（`st.secrets` のパスワード）
- [ ] 参加数・完了数・中断数、条件別の回答数・時間切れ数
- [ ] 生データ CSV 出力（直接識別情報を含まないこと）

### M5 予備実験準備

- [ ] 説明文・同意文案（`docs/participant/`）
- [ ] 実験者向け操作手順（`docs/operator_guide.md`）
- [ ] AppTest による模擬参加者 N 人の通し実行で、CSV が別環境で再集計できることを確認
