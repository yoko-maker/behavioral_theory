# フェーズ3：行動ログ 実行計画

概要書 §6.3・§6.4・§10・§13 フェーズ3に対応する。

## 方針（2026-10-02 ユーザー決定）

| 項目 | 決定 |
| --- | --- |
| 実装方式 | 問題画面（問題文・選択肢・入力欄・回答ボタン・残り時間）を JavaScript の部品として自作する（Streamlit components v2） |
| 記録範囲 | 概要書 §6.4 の範囲すべて：マウス座標・押下・選択の変更・選択肢への出入り・キー操作の種類（内容は記録しない）・タブ切替／ウィンドウの非アクティブ化 |
| 座標の細かさ | 画面更新ごと（requestAnimationFrame、約60回/秒）。動いていない間は記録しない |
| 端末情報 | 大まかな種類のみ：ブラウザ・OS の種類、表示領域・問題領域の大きさ、画素比、入力の種類（マウス／タッチ／ペン） |

## 設計

### 問題画面の部品（`app/components/trial_panel.*`）

- 問題文は `textContent` で表示する（HTML として解釈しない）。
- 表示時刻（`performance.now()`）を基準に、イベントをブラウザ内に蓄積し、回答確定・時間切れのときにまとめて送る（§6.4）。
- 座標は問題領域（部品の外枠）を基準に 0〜1 へ正規化する。領域の外では 0 未満・1 超になる。
- 表示直後に選択肢・入力欄・ボタンの位置（正規化した矩形）を `layout` イベントとして記録する（軌跡の図で選択肢の位置を示すため）。
- 残り時間の表示・時間切れの検知はブラウザでも行うが、**時間切れの判定はサーバーが正**とする。ブラウザからの時間切れ通知がサーバーの期限より早い場合はイベントだけ保持し、サーバーの判定を待つ。
- 数値入力の検証はブラウザでも行う（サーバーと同じ規則）。サーバーでも再検証する。
- 再描画で部品が作り直されても状態が失われないよう、試行ごとの状態を `window` 上に試行IDで保持する。

### 受け取りと保存

- ブラウザから届くデータは信頼できない入力として `domain/client_log.py` で検証する（イベント種別の許可リスト・件数上限・値の範囲）。
- 試行の行とイベントは同じトランザクションで保存する。重複送信ではイベントを重ねて保存しない。
- trials に端末情報とログの状態（`client_log_status`：`ok` / `missing`）を追加する。ブラウザから何も届かずにサーバー側で時間切れにした試行は `missing`。
- `shown_at_client_ms` / `submitted_at_client_ms` に値が入る。`response_time_ms`（サーバー計測）の意味は変えない。ブラウザ側の回答時間は両者の差で求める。
- `revision_count` をブラウザで数える。選択式は最初の選択後の変更回数（見直しで初回回答が選択済みなら最初の変更から）、数値入力式は文字を削除した操作の回数。

### 指標（`analysis/trajectory.py`、定義は事前に固定）

指標は回答形式で分ける（2026-10-02 ユーザー決定）。軌跡の指標・図は選択式のみ。数値入力式はカーソルが入力欄に向かうだけで軌跡から判断の過程をほとんど読み取れないため、キー操作の時間の指標を使う。

**選択式（マウス軌跡）**

| 指標 | 定義 |
| --- | --- |
| 軌跡長 | 隣接点間距離の合計（正規化座標に問題領域の幅・高さを掛けた CSS px） |
| x 方向転換 | x 方向の移動の向きが反転した回数（0.01 未満の移動は無視） |
| 初動時間 | 表示から最初の move までの ms |
| 選択肢への進入 | `choice_enter` の回数（最終回答以外の選択肢への進入を別に数える） |
| 非表示時間 | タブ切替等で画面が非表示だった合計 ms |

**数値入力式（キー操作の時間）**

| 指標 | 定義 |
| --- | --- |
| 最初の入力まで | 表示から最初の `input_edit` までの ms |
| 入力中の最長の間 | 連続する `input_edit` の間隔の最大値（ms） |
| 最後の入力から確定まで | 最後の `input_edit` から `submit` までの ms（回答した試行のみ） |
| 入力操作数・削除操作数 | `input_edit` の件数と、そのうち削除（`op=delete`）の件数 |
| 非表示時間 | 選択式と同じ |

### 実験者画面

- 「操作ログ」タブ：ログ取得状況（ブラウザ・OS・入力の種類別の `ok` 率、イベント数）、試行別の指標、軌跡の図（時刻で色分け、時刻スライダーで途中までを表示＝簡易再生、選択肢の位置を矩形で表示）、条件・問題ごとの重ね合わせ。

### 確信度の画面（2026-10-02 追加・ユーザー決定）

- 確信度の画面も同じ部品（`format: "scale"`、段階を横に並べる）で描画し、同じ種類の操作を記録する。
- 操作は評価対象の試行の `trial_id` で保存し、`events.phase`（`answer` / `confidence`）で画面を区別する。**回答の画面の指標・図は必ず `phase=answer` に絞る**（`analysis/trajectory.py` の `phase_events`）。
- trials に確信度の回答時間（ブラウザ計測）・選び直し回数・ログの状態・イベント数を追加する。
- 指標：確信度の回答時間、選び直し、他の段階への進入（最終的に選んだ段階以外の `choice_enter`）、移動点数、x 方向転換。迷いと関係しうる手がかりとして扱い、迷いそのものとは解釈しない。
- **指標の定義は検討中**：手の動きの個人差が混ざる懸念があるため、[confidence_metrics_definition.md](confidence_metrics_definition.md) で定義案を検討し、予備実験の結果を見る前に確定する。現在の指標は記述用。

## 決定事項ログ

| 日付 | 決定 | 理由 |
| --- | --- | --- |
| 2026-10-02 | 時間切れの判定はサーバーを正とする | ブラウザの時計・タブの非アクティブ化による誤差で、条件間の制限時間がずれないようにするため |
| 2026-10-02 | `response_time_ms` はサーバー計測のまま。ブラウザ側の回答時間は別列の差で求める | 既存データと列の意味を変えないため |
| 2026-10-02 | AppTest での部品操作は Streamlit の内部 API を使う補助関数に閉じ込める | 公開 API で部品の送信を模擬できないため。Streamlit 更新時はこの補助関数だけ直せばよいようにする |
| 2026-10-02 | 期限後、ブラウザからの時間切れ通知を最大 2 秒待ってからサーバー側で時間切れを確定する | 通知に操作ログが含まれるため。届かなければログなし（`client_log_status=missing`）で記録する |
| 2026-10-02 | 部品と同じ数値解釈規則をブラウザ側にも持ち、Node.js で一致を検査する | 送信前に入力エラーを出すため。規則がずれるとブラウザとサーバーで判定が食い違う |
