# 確信度の画面の指標：定義案（検討中）

**ステータス：** 案（2026-10-02 作成）。予備実験の結果を見る前に確定する。確定までは実装を変更しない。
**関連：** [phase3.md](phase3.md)、[データ辞書](../data_dictionary.md)、概要書 §6.4・§10・§12.3

## 1. 目的と前提

確信度の画面での操作（決めるまでの時間・選び直し・カーソルの動き）から、確信度の数字だけでは見えない「決め方の違い」を、条件間で比較できるようにする。

- これらの指標は **迷いと関係しうる手がかり** であり、迷いそのものの測定ではない。
- 手の動きには、判断と無関係な個人差が大きい（カーソルを回す癖、手の落ち着かなさ、タッチパッドとマウスの違い、手の震えなど）。**この個人差が指標に混ざること** を最大の交絡として扱う。
- 結果は条件単位の傾向として扱い、個人の判断・特性の推定には使わない。**手の動きから注意欠如・多動症（ADHD）などの特性を推測したり、記録したりしない**（研究目的外であり、倫理上も扱わない）。

## 2. 現在の指標と問題点

| 指標（現在の列名） | 定義 | 問題点 |
| --- | --- | --- |
| 確信度の回答時間_ms | 画面表示から「次へ」までの時間 | 操作の速さの個人差を含む |
| 選び直し | 最初の選択後に別の段階を選んだ回数 | 問題は小さい（クリックを伴う意図的な操作のみを数える） |
| 他の段階への進入 | 最終的に選んだ段階以外の枠にカーソルが入った回数 | **通り過ぎただけでも数える。** 手をよく動かす人ほど迷いと無関係に大きくなる |
| x方向転換 | カーソルの左右の向きが入れ替わった回数 | 手の動きの癖の影響が大きい |
| 移動点数 | カーソル位置の記録数 | 画面の更新回数（端末）と動きの量に依存する |

## 3. 指標の位置づけ（案）

| 区分 | 指標 | 理由 |
| --- | --- | --- |
| **主** | 選び直し | 手の動きの癖の影響が最も小さい |
| **主** | 確信度の回答時間（本人の基準で補正、§5） | 考えていた時間を反映しやすい。操作の速さの個人差は補正で減らす |
| **補助** | 立ち止まった段階の数（§4、本人の基準で補正） | 「止まって考えた枠」に近づけた軌跡由来の指標 |
| **記述のみ** | 他の段階への進入（現定義）、x方向転換、手の動きの量（§6） | 癖の影響が大きいため、仮説の検証には使わず、分布の記述・データ品質の確認に使う |

## 4. 「立ち止まった段階」の定義（案）

枠の上を通過しただけの場合と、枠の上で止まって考えた場合を分ける。**時間だけでなく速さでも判定する**（枠の中でカーソルを回し続けている状態は「止まった」と見なさない）。

> ある段階の枠の中で、カーソルの速さが **V_stop 未満の状態が T_dwell 以上続いた** とき、その段階に「立ち止まった」と数える。最終的に選んだ段階は数えない。

- 速さは、隣接する移動点の間の距離 ÷ 時間で求める（単位：画面上の px/秒）。
- 枠の範囲は、表示直後に記録した位置（`layout` イベント）を使う。
- 同じ枠で、立ち止まり → 移動 → 再び立ち止まり、となった場合は2回と数える（要検討）。

| パラメータ | 候補 | 決め方 |
| --- | --- | --- |
| T_dwell（止まっている時間） | 200 ms 前後 | §7 の手順で決める |
| V_stop（止まっているとみなす速さ） | 未定 | §7 の手順で決める |

## 5. 本人の基準による補正（案）

個人差を打ち消すため、本番の値を **同じ参加者の練習課題の確信度の画面の値** と比べる。

- 練習課題（2問）でも確信度を答えてもらっているため、新しい計測は不要。
- 補正の方法の候補：
  - 差：本番の値 − 練習の平均
  - 比：本番の値 ÷ 練習の平均（回答時間のように正の値をとる指標）
- 限界：練習が2問しかないため、基準の推定は不安定。
  - 対策の候補：(a) 練習を増やす、(b) 判断を伴わない基準課題（例：指定された段階を選ぶだけの画面）を追加する。どちらも参加者の負担と所要時間が増えるため、要検討。

## 6. 手の動きの量（記述用）

参加者ごとの「手の動きの多さ」を、練習課題の確信度の画面での **1秒あたりの移動距離** で表す。分析では、条件間の比較の共変量として使うか、分布の確認に使う。特性の推定には使わない。

## 7. パラメータの決め方（手順）

1. 予備実験のデータでは、**移動の速さと枠の中での滞在時間の分布だけ** を見て T_dwell・V_stop を決める。正誤・確信度・条件ごとの結果は見ない。
2. 決めた値と理由を、このファイルの決定事項ログに記録してから本実験・本分析に進む。
3. 本分析では、T_dwell・V_stop を前後に変えても結論が変わらないかを確認する（感度分析）として併せて報告する。

## 8. 欠損の扱い

- マウス・タッチを使わずキーボードだけで操作した場合、軌跡由来の指標は **0 ではなく欠損** とする（動きがなかったのではなく、測れていない）。
- 確信度の画面のログが届かなかった試行（`confidence_client_log_status = missing`）も欠損とする。
- 欠損の件数と理由は、条件ごとに報告する。

## 9. 実装に必要な変更（確定後に行う）

- 確信度の画面の大きさ（幅・高さ）を記録する。**現在は回答の画面の大きさしか記録していない**ため、速さを px/秒で求められない。
- `analysis/trajectory.py` に §4〜§6 の指標を追加し、実験者画面に表示する。
- 定義をテストで固定する（境界値：ちょうど T_dwell、ちょうど V_stop など）。

## 10. 確認していただきたい点

1. 指標の位置づけ（§3）：主・補助・記述の区分でよいか。
2. 本人の基準による補正（§5）：練習2問で足りるか。基準課題を追加するか。
3. 同じ枠での複数回の立ち止まりの数え方（§4）。
4. パラメータを決める手順（§7）で、予備実験のどの範囲のデータを使ってよいか。
5. 倫理審査で、手の動きのデータの扱い（§1 の方針）を説明する必要があるか。
