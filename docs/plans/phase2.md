# フェーズ2：実験制御の強化 実行計画

概要書 §13 フェーズ2・§4.3 に対応する。確信度入力・重複送信の検知はフェーズ1で実装済み。

## 方針（2026-10-02 ユーザー決定）

| 項目 | 決定 |
| --- | --- |
| 割当 | 条件 × 出題順 の組（セル）のうち、割当人数が最も少ないセルに割り当てる。同数なら seed による無作為 |
| 見直し | 条件ごとに「見直しあり／なし」を設定可能。ありの場合、全問の回答後に各本課題を再提示し、見直し後の回答を別行（`attempt=revised`）で保存 |
| 再読み込み | 再開はさせず、中断として記録して案内を出す |
| 条件設定画面 | 閲覧と受付の開始／停止のみ。条件の変更は YAML で行う |

## 設計

### 割当（M1）

- 出題順は本課題のラテン方格の回転（n 題なら n 通り）。2 題なら「リンダ先」「バットとボール先」の 2 通り。練習の順は固定。
- 実験定義の `counterbalance_order: true` で有効化。セル = 条件 × 回転番号。
- 割当人数は `completed` と、開始から `abandon_after_min` 分以内の `in_progress` を数える（中断者・放置者は数えない）。
- 割当と参加者レコード作成は1トランザクションで行い、同時参加でも同じ集計に基づいて割り当てる。
- participants に `order_index`・`assignment_method` を記録する。

### 見直し（M2）

- 条件の `allow_revision: true` で有効化。本課題の後に「見直しの説明」→ 各本課題を元の提示順で再提示する。
- 再提示時は初回回答を表示し、変更してもそのままでもよい。**見直しには制限時間を設けない**（記録上 `time_limit_sec` は空）。
- 見直しの行は新しい trial として保存し、`attempt=revised`、`initial_trial_id` に初回の trial_id を持つ。初回が時間切れの問題も再提示する。
- 確信度を取得する条件では、見直し後にも確信度を尋ねる。
- 練習は見直しの対象にしない。

### 中断（M3）

- 同意後、URL に参加者ID（`?pid=`）を付ける。再読み込み・別タブで同じ URL が開かれ、セッションに状態がない場合は、その参加者を `aborted`（`abort_reason=reload`）にし、中断の案内を表示する。
- 完了済みの参加者の URL を開いた場合は終了画面を表示し、状態は変えない。
- タブを閉じて戻らない参加者は `in_progress` のまま残る（割当の集計では `abandon_after_min` で除外）。

### 受付と条件設定画面（M4）

- 受付状態は追記のみのログ（`experiment_status_log`）で管理し、最新の行を現在の状態とする。**既定は受付停止**。
- 受付停止中は新しい参加者が同意に進めない。参加中の参加者は最後まで続けられる。
- 実験者画面にタブを追加：実施状況／条件設定（定義・問題文の版・セル別人数・受付切替）。

## 既知の制約

- 割当の集計は「同意した時点」で行う。説明画面を開いたまま長時間放置した参加者も、同意時点の人数で割り当てられる。
- 回線断で Streamlit のセッションが切れて再接続した場合も、再読み込みと同じく中断として記録される。
- 別タブで同じ URL が開かれた場合、元のタブは次の送信時に中断画面へ切り替わる（それまでは表示されたまま）。

## 決定事項ログ

| 日付 | 決定 | 理由 |
| --- | --- | --- |
| 2026-10-02 | 出題順はラテン方格の回転 | 題数が増えても順序数が n に収まり、各問が各位置に均等に現れる |
| 2026-10-02 | 見直しには制限時間を設けない | 初回（時間制約下）と熟考後の回答を対比するため。必要なら条件項目として追加する |
| 2026-10-02 | 受付状態の既定は停止 | 意図しない参加者データの混入を防ぐため、実験者が明示的に開始する |
| 2026-10-02 | 操作説明の「戻って変更できない」を「回答した問題に戻ることはできない」に変更 | 見直しあり条件でも事実と矛盾しない表現にするため |
| 2026-10-02 | 中断済みの参加者の保存を拒否し、元のタブも中断画面にする | 別タブ・再読み込み後に元のタブから回答が続き、`aborted` が `completed` で上書きされるのを防ぐため |
| 2026-10-02 | 見直しでは初回回答を既定値として選択・入力済みにする | 「変更してもそのままでもよい」を1操作で選べるようにするため。変更回数は既定値からの変更を数える |
| 2026-10-02 | 見直しは事前に告知しない（ユーザー決定） | 初回回答が見直しの有無の予告に影響されないようにするため。操作説明・同意文に見直しを示す記述を入れない。見直しの説明は見直し直前の画面（`experiments/texts/review_intro.md`）でのみ行う |
| 2026-10-02 | 確信度の取得は予備実験でも残す（ユーザー決定） | 分析に使うかはあとから選べるが、取っていないデータはあとから取れないため。反応性（以降の回答への影響）は全条件共通。外す場合は条件の `collect_confidence: false` のみで対応できる |
